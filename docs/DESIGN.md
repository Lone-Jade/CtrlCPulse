# 设计说明

这份文档记录 CtrlCPulse 的实现取舍。目标不是复述代码，而是解释"为什么是这样"，以及哪些看起来奇怪的地方其实是刻意的。

## 1. 目标与非目标

**要做的事**：在按下 `Ctrl + C` 之后，用一个不打扰人的方式确认"剪贴板里现在是什么"，覆盖文字、图片、文件三类内容，并在开机后自动驻留。

**不做的事**：

- 不做剪贴板历史（不落盘、不提供回溯列表）；
- 不做跨设备同步（不联网）；
- 不替换系统通知中心，也不追求"系统级"外观。

非目标决定了后面一系列技术选择：既然不保存数据，就不需要数据库、不需要服务、不需要后台常驻进程之外的任何组件。

## 2. 为什么自绘卡片，而不是系统 Toast

Windows 10/11 的 Toast 通知（`Windows.UI.Notifications`）看起来是"正确"的选择，但实际用起来有三个问题：

1. **需要身份**。未打包的桌面应用要发 Toast，得注册 AppUserModelID、创建快捷方式并写入 `Start Menu`，否则通知根本不显示；调试成本高，卸载残留也多。
2. **不可控**。样式、停留时长、圆角、堆叠位置都由系统决定，无法做出"贴着右下角、三张堆叠、点击即关"的紧凑效果。
3. **会被吞**。专注助手（Focus Assist）、通知优先级、勿扰模式都可能让通知不出现——而这恰恰是"确认复制成功"最不能接受的失败方式。

因此卡片完全自绘：一个无边框、分层（layered）、不抢焦点的顶层窗口，用 `UpdateLayeredWindow` 把 32 位 ARGB 位图直接贴到屏幕上。系统只负责合成，样式完全由我们控制。

## 3. 进程模型

单进程、单线程 UI（STA）：

```text
Program.Main
  ├─ SingleInstance           互斥量 + 激活事件
  ├─ TrayContext : ApplicationContext
  │    ├─ NotifyIcon + ContextMenuStrip
  │    ├─ ClipboardWatcher    隐藏 NativeWindow，收 WM_CLIPBOARDUPDATE
  │    ├─ ToastQueue          卡片栈与布局
  │    └─ SettingsStore       <exe 目录>\settings.ini（便携）
  └─ Application.Run(context)
```

没有后台服务、没有驱动、没有全局键盘钩子。监听的是**剪贴板变化**而不是按键——这带来两个好处：

- 不需要 `WH_KEYBOARD_LL` 这类常驻钩子，不会被安全软件当成键盘记录器；
- 用户在任意程序里用菜单"复制"、拖拽、截图工具写入剪贴板，同样会提示，行为更符合"剪贴板变了"的语义。

代价是：它无法区分"用户按了 Ctrl+C"和"程序自己写了剪贴板"。对确认类提示来说，这个差异可以接受。

## 4. 剪贴板监听：防抖、去重、重试

`AddClipboardFormatListener` 会在剪贴板每次变化时向窗口投递 `WM_CLIPBOARDUPDATE`。真实场景里这个事件有三个坑：

**坑一：一次复制触发多次。** 某些程序会分几步写入剪贴板（先清空、再写格式），导致连续多条消息。处理方式是 120 ms 防抖：收到消息只重启计时器，安静下来才真正读取。

**坑二：重复读取同一份内容。** 即使防抖，也可能因为无关的剪贴板写入（比如输入法、剪贴板管理器）重复提示。处理方式是用 `GetClipboardSequenceNumber()` 作为内容版本号：只有序列号变化才提示。序列号由系统在剪贴板内容变化时递增，比比较内容本身便宜且可靠。

**坑三：剪贴板被别的进程占用。** `OpenClipboard` 可能因为其他程序正持有剪贴板而失败，抛出 `ExternalException`。处理方式是 6 次重试、间隔 45 ms（约 270 ms 窗口），足够跨过绝大多数瞬时占用；仍失败就静默放弃——确认提示失败比弹错误框更合适。

## 5. 内容类型判定：Files > Image > Text

剪贴板是"多格式容器"，一次复制往往同时存在多种格式。判定顺序固定为：

```text
有 FileDrop            → 文件
否则有位图（Bitmap/DIB）→ 图片
否则有文本             → 文字
```

顺序不能反：在资源管理器里复制文件时，剪贴板同时包含 `FileDrop` 和文件名的文本表示；先判文本会把"复制了 3 个文件"显示成"复制了一串路径"。

图片与文本同时存在时需要再看一层：

- 若同时带 `HTML Format` 或 `RTF`（Word、Excel、网页富文本），按**文字**处理——用户复制的是"内容"，不是一张图；
- 若只有位图 + 纯文本（浏览器"复制图片"常见），按**图片**处理。

这条规则来自实际使用中的直觉：从 Excel 复制单元格，用户想确认的是"我复制了那段文字"；从网页复制图片，用户想确认的是"图片进来了"。

## 6. 隐私：跳过带忽略标记的内容

密码管理器（1Password、KeePass、Bitwarden 等）在把密码写入剪贴板时，会额外写一个名为 `Clipboard Viewer Ignore` 的格式，通知剪贴板查看器"不要显示/记录这段内容"。

CtrlCPulse 默认尊重这个标记：检测到该格式就直接跳过，不读文本、不生成快照、不弹卡片。设置项 `ignoreSecret` 可以关掉，但默认开启。

这不是"额外功能"，而是剪贴板工具的底线：一个会把你刚复制的密码显示在屏幕上的工具，是不合格的。

## 7. 渲染管线

每张卡片是一个 `ToastForm`，生命周期内只做三件事：

```text
构造时：GDI+ 在 32bpp 位图上画一次完整卡片（阴影、圆角、色条、图标、标题、正文、缩略图）
显示时：UpdateLayeredWindow 把位图贴到屏幕，逐像素 alpha 生效
动画时：只改窗口位置（滑动）和 SourceConstantAlpha（淡入淡出），不重绘位图
```

**为什么只画一次**：卡片内容在显示期间不变，逐帧重绘既浪费 CPU，也容易在低端机上抖动。把"内容"和"动画"解耦之后，动画只是移动一个已经画好的位图，代价极低（实测空闲与动画期间 CPU 都接近 0%）。

**阴影**：没有用 `DropShadow` 之类的系统效果（分层窗口不支持），而是手工画 8 层圆角矩形，逐层向外偏移、降低 alpha，形成柔和的假阴影。这是分层窗口下最省事的近似方案。

**圆角**：`GraphicsPath` + `AddArc` 构造圆角矩形，配合 `SetClip` 让卡片内容和阴影都遵守同一轮廓。

**淡入淡出**：`BLENDFUNCTION.SourceConstantAlpha` 从 0 到 255，配合 180 ms 三次缓出曲线；滑入 18 px（96 DPI 基准），滑出 10 px / 160 ms。缓出曲线让"出现"显得干脆，"消失"显得轻。

## 8. 不抢焦点

这是提示类窗口最容易做错的地方：一个会抢焦点的提示，会打断用户正在输入的内容。

三层保险：

1. `WS_EX_NOACTIVATE`：点击窗口不会激活它；
2. `ShowWithoutActivation` 返回 `true`：`Show()` 不抢前台；
3. 处理 `WM_MOUSEACTIVATE` 返回 `MA_NOACTIVATE`：即使系统尝试激活也拒绝。

再加 `WS_EX_TOOLWINDOW`，让它不出现在 Alt+Tab 里；`TopMost` 保证它盖在普通窗口之上。验收脚本会对比卡片出现前后的前台窗口句柄，确认没有变化。

## 9. 鼠标交互的两个边界

**阴影区要能穿透。** 窗口比卡片大（四周各留 14 px 阴影边距），如果整块窗口都吃鼠标，光标停在卡片旁边的空白处也会被当成"悬停在卡片上"。因此处理 `WM_NCHITTEST`：落在卡片矩形内返回 `HTCLIENT`，否则返回 `HTTRANSPARENT`，让点击和悬停穿透到下层窗口。

**悬停暂停要有前提。** 悬停暂停自动消失是常见体验，但存在一个尴尬场景：用户把鼠标停在屏幕右下角（托盘区附近），卡片恰好出现在光标下面，于是这张卡片永远不消失。解决办法是记录"卡片出现时光标是否已经在卡片范围内"：

- 已在范围内 → 本张卡片不启用悬停暂停，正常计时消失；
- 不在范围内 → 之后鼠标移入才暂停，移出恢复计时。

## 10. 堆叠与布局

`ToastQueue` 是一个栈：最新卡片在**最下面**（贴近工作区底边），旧卡片被顶上去。

```text
        ┌──────────────┐  ← 最旧，超时先消失
        └──────────────┘
        ┌──────────────┐
        └──────────────┘
        ┌──────────────┐  ← 最新
        └──────────────┘  ← 距工作区底边 12 px（96 DPI 基准）
```

规则：

- 同时可见上限来自设置（默认 3，范围 1–5）；超过时最旧的一张立即淡出；
- 新卡片插入后，其余卡片瞬时上移（不做位移动画，避免和淡入动画打架）；
- 布局以 `Screen.PrimaryScreen.WorkingArea` 为基准，自动避开任务栏；卡片总高度超出工作区时整体上移，保证不越界。

## 11. DPI

Windows 的缩放是这类小工具的重灾区。做法：

- 清单声明 `dpiAwareness = permonitorv2`，进程拿到真实物理像素；
- 启动时用 `Graphics.FromHwnd(IntPtr.Zero).DpiX / 96f` 得到主屏缩放；
- `Theme.Px()` 把所有 96 DPI 基准尺寸换算成物理像素（宽 344、高 84/96/108、圆角 12、边距 16/12、阴影 14 等）；
- `AutoScaleMode = None`：尺寸已经手工缩放，关掉 WinForms 的自动缩放，避免二次放大。

字体统一用 `GraphicsUnit.Pixel`，保证在 125% / 150% 下字号与布局比例一致。

## 12. 配置

`settings.ini` 与 `error.log` 都放在 exe 同目录（便携模式），是手写的键值文件，不引入 JSON/XML 依赖（.NET Framework 下 `System.Text.Json` 需要额外包，`DataContractJsonSerializer` 又过于笨重）。解析器只做三件事：容错（缺键用默认值、坏值回落）、钳制（`maxVisible` 1–5、停留 800–10000 ms）、原子写（先写临时文件再替换，避免断电留下半个文件）。

目录跟随 exe 而不是 `%APPDATA%`：一是保持便携（整个文件夹拷走即可），二是这个工具默认安装在非系统盘，配置也应当跟着走，不在 C 盘留任何文件。

## 13. 单实例

```text
Mutex  "CtrlCPulse.Instance.v1"   → 谁是第一个进程
Event  "CtrlCPulse.Activate.v1"   → 通知第一个进程"有人又启动了"
```

第二个进程发现互斥量已存在，就 `Set` 一次事件后退出；第一个进程的监听线程收到事件，在 UI 线程弹一张"已在运行"的卡片。

这里踩过一个坑：`Dispose` 里无条件 `Set` 事件，导致第二个进程退出时又通知了一次，于是弹出两张"已在运行"。修正后只有互斥量持有者在退出时 `Set`，用来唤醒监听线程收尾。

另一个坑是线程切换：`TrayContext` 在 `Application.Run` 之前构造，此时 `SynchronizationContext.Current` 还不可用，直接 `Post` 会落到线程池线程上——那里的窗口没有消息循环，卡片的计时器不会走，卡片就永远不消失。修正方式是创建一个隐藏 `Control`，用 `Control.BeginInvoke` 把回调切回 UI 线程。

## 14. 开机自启

写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值为 `"<exe 路径>" --tray`。

选择 HKCU 而不是 HKLM 的原因：不需要管理员权限，卸载干净，符合"当前用户的小工具"定位。如果注册表写入失败（极少数被策略锁定的环境），回退到启动文件夹快捷方式（`WScript.Shell` 创建 `.lnk`）。

托盘菜单里的"开机自动启动"开关直接读写同一个注册表值，和安装脚本保持单一事实来源。

## 15. 图标

`tools/make-icon.ps1` 用 GDI+ 画一个圆角渐变方块 + 白色对勾，导出 9 种尺寸（16–256）的 ICO（大尺寸用 PNG 负载）。全部由脚本生成，仓库里不放第三方图标素材，也方便随时改配色重新生成。

## 16. 构建

机器上没有 .NET SDK，也不想为了一个 100 KB 的小工具装 200 MB 的 SDK。因此 `build.ps1` 直接找 Roslyn 的 `csc.exe`（优先 VS Build Tools 2022 的固定路径，其次 VS 安装目录，最后 `vswhere`），用 `/noconfig` + 显式 `/r:` 引用 .NET Framework 4.8 的程序集编译。

关键参数：

```text
/target:winexe                 不弹控制台
/platform:anycpu               
/win32icon:assets\app.ico      资源管理器里的图标
/win32manifest:assets\app.manifest   DPI 与兼容性声明
/resource:assets\app.ico,CtrlCPulse.app.ico   托盘图标（嵌入资源）
```

自检程序（`CtrlCPulse.SelfTest.exe`）用同一批源码但排除 `Program.cs`，以 `/target:exe` 编译，便于在控制台看结果。

## 17. 错误处理

- `Application.ThreadException` 与 `AppDomain.UnhandledException` 都写入 exe 同目录的 `error.log`，避免静默闪退；
- 剪贴板读取失败、托盘图标加载失败等可恢复错误就地吞掉并降级（例如没有图标就用系统默认图标）；
- 卡片渲染异常时关闭该卡片，不影响后续提示。

## 18. 已知取舍

- **多显示器**：只贴主屏右下角。跟随鼠标所在屏更"聪明"，但会让布局与验收逻辑复杂一倍，当前版本先不做。
- **富文本**：只取纯文本预览，不渲染格式。渲染 RTF/HTML 需要额外解析器，收益有限。
- **通知优先级**：不做"仅静音模式""游戏时暂停"等场景感知，交给用户用托盘左键手动暂停。
- **本地化**：界面与注释为中文，未做多语言资源。
