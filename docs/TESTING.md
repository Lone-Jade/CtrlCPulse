# 测试说明

这个项目的验收不靠"看起来没问题"，而是三套可以反复执行的脚本。它们各自回答不同的问题：

| 套件 | 命令 | 断言数 | 回答的问题 |
| --- | --- | --- | --- |
| 逻辑自检 | `.\build.ps1 -Test` | 25 | 纯函数算得对吗？ |
| 端到端功能 | `pwsh -STA -NoProfile -File .\tools\verify-clipboard.ps1` | 13 | 真实剪贴板变化能走通整条链路吗？ |
| 视觉验收 | `.\tools\verify-visual.ps1` | 44 | 画出来的东西，几何和像素符合设计吗？ |

三套都返回退出码 0 表示全部通过；失败会打印 `FAIL` 行并以 1 退出。

## 1. 逻辑自检（25 项）

编译产物是 `dist\CtrlCPulse.SelfTest.exe`，与主程序共享除 `Program.cs` 之外的全部源码，因此测的是**真实实现**而不是复制品。

覆盖范围：

- **文本快照**：单行、多行行数统计、空白折叠、超长截断（200000 字符上限）、纯空白内容忽略、代理对（emoji）不被截断成半个字符；
- **文件快照**：数量与总体积、超过 3 个文件时的省略写法、空输入；
- **图片快照**：等比缩略图（最大 184×116）、小图不放大、竖图受高度限制、空输入；
- **格式化**：体积单位（B/KB/MB/GB）；
- **设置**：读写往返、损坏文件回落默认值、超范围值钳制；
- **开机自启**：注册表值写入/读取/删除（用可注入的子键名，不污染真实 `Run` 项）；
- **去重**：`GetClipboardSequenceNumber` 比较逻辑；
- **主题**：DPI 缩放换算；
- **资源**：嵌入的图标资源可加载；
- **隐私**：`Clipboard Viewer Ignore` 格式识别；
- **类型标签**：文本/图片/文件的中文标签；
- **快照释放**：`Dispose` 后缩略图释放。

运行示例：

```text
CtrlCPulse 自检
----------------
PASS  文本快照 - 单行
...
结果: 25 通过, 0 失败
```

## 2. 端到端功能（13 项）

脚本必须用 STA 运行，因为 `System.Windows.Forms.Clipboard` 要求单线程单元：

```powershell
pwsh -STA -NoProfile -File .\tools\verify-clipboard.ps1
```

它做的是"真的去改剪贴板，然后看窗口"：

1. 清空配置，启动应用，确认**首次运行欢迎卡片**出现并自动消失；
2. 写入文字 → 确认文本卡片出现（窗口高度 = 文本卡片规格）并自动消失；
3. 写入图片 → 确认图片卡片出现（更高的窗口，带缩略图）；
4. 写入两个文件的 `FileDrop` → 确认文件卡片出现；
5. 写入带 `Clipboard Viewer Ignore` 标记的文本 → 确认**不弹**卡片；
6. 再启动一个实例 → 确认新进程在 5 秒内退出（退出码 0），且已有实例弹出"已在运行"卡片；
7. 静置 2 秒，测量空闲 CPU 与常驻内存（预算：CPU < 5%，内存 < 120 MB）。

窗口是否存在通过 `EnumWindows` + `GetWindowThreadProcessId` 判断，高度与规格比对，因此能区分"弹了卡片"和"弹了正确类型的卡片"。

测试结束后会**恢复测试前的剪贴板内容**（文字/图片/文件列表三选一），临时文件会清理。

## 3. 视觉验收（44 项）

```powershell
.\tools\verify-visual.ps1
```

这个脚本解决一个具体问题：开发环境里没有人眼能可靠地"看"截图，所以把视觉检查拆成**窗口几何**和**像素断言**两部分。

### 几何部分（每张卡片 5 项）

通过 `EnumWindows` 拿到卡片窗口的真实矩形（脚本先声明 Per-Monitor V2 DPI 感知，避免坐标被系统虚拟化），断言：

- 窗口宽 = 卡片宽 344 + 2×阴影 14（96 DPI 基准，按缩放换算）；
- 窗口高 = 卡片高（84/96/108）+ 2×阴影；
- 右边缘 = 工作区右边 - 16；
- 下边缘 = 工作区底边 - 12；
- `ExStyle` 同时具备 `LAYERED`、`NOACTIVATE`、`TOOLWINDOW`、`TOPMOST`。

### 像素部分（每张卡片 8 项）

把屏幕右下角 720×660 区域截成位图，用纯字节扫描：

- 左侧类型色条存在，颜色分别为文本 `#5C94FF`、图片 `#AC74FF`、文件 `#F5B04A`，宽度 4 px（96 DPI 基准）；
- 色条紧贴卡片左边（误差 ≤3 px）；
- 色条纵向跨度合理（被圆角裁掉约 4 px/端）；
- 卡片内部为深色半透明（luma < 110）；
- 左上圆角处透明（圆角像素接近桌面底色）；
- 对勾图标区域有亮像素；
- 标题文字区域有亮像素；
- 三张卡片同屏时纵向堆叠、总高度符合规格。

### 其它断言

- 卡片出现前后前台窗口句柄不变（**不抢焦点**）；
- 演示结束后可见窗口数为 0、屏幕无残留色条像素。

### 为什么这样测

- 色条检测用"逐列统计匹配像素数"而不是"取所有匹配像素的外接矩形"：壁纸里可能恰好有接近色条颜色的像素，外接矩形会被拉大；色条是连续整列，按列统计能稳定命中。
- 卡片高度从**窗口矩形**读，而不是从像素推断：色条被圆角裁切，像素高度会短 8 px 左右，容易误判。
- 截图存到 `dist\verify\`（已加入 `.gitignore`），失败时可以直接打开比对。

## 4. 手工检查清单

自动化覆盖不到的部分，建议安装后手工过一遍：

1. 在记事本里选中一段文字按 `Ctrl + C` → 卡片显示文字预览；
2. 在资源管理器里选中 2–3 个文件按 `Ctrl + C` → 卡片显示文件数量与总大小；
3. 用 `Win + Shift + S` 截图（自动进剪贴板）→ 卡片显示图片缩略图；
4. 在 Excel 里复制单元格 → 卡片按**文字**显示（不是图片）；
5. 用密码管理器复制密码 → 默认**不弹**卡片；
6. 连续快速复制 5 次 → 最多同时看到 3 张，最旧的先消失；
7. 把鼠标停在卡片上 → 卡片暂停消失，移开后继续计时；
8. 点击托盘图标 → 暂停；再点 → 恢复，并弹出状态卡片；
9. 右键托盘 → 依次切换"忽略私密内容""开机自动启动"，确认弹出的状态卡片文案与注册表/设置文件一致；
10. 重启（或注销再登录）→ 托盘图标自动出现。

## 5. 已知限制

- 视觉验收依赖主屏分辨率与缩放；换到 100%/150% 或不同分辨率时，脚本会按 `DpiX` 自动换算，但截图裁剪区域固定为 720×660，极小分辨率下会退化。
- 端到端脚本会临时改写系统剪贴板（结束时恢复），运行期间不要复制重要内容。
- 两套脚本都会启动/结束 `CtrlCPulse.exe` 进程；如果用户正在使用已安装的实例，脚本会先结束它。
- 没有做 UI 自动化点击托盘菜单（需要 UIA + 托盘溢出区定位，稳定性差），菜单项逻辑由"预览样式"演示模式和设置读写自检间接覆盖。
